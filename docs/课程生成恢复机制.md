# 课程生成恢复机制 · 设计

> 目标：课程生成是长任务，任何中断（模型自停、上游报错、断网、进程重启）都不能让已完成的章节白做，且能自动或一键继续。

---

## 一、问题拆解

当前实现把「整门课」压在一次 run 里：

```text
create_course(17 课) → write_lesson × 17 → 结束
```

一次 run 要经历几十次模型调用，任何一步失败，整条链就停在那里，且没有检查点。

| 中断源 | 现状 | 后果 |
|---|---|---|
| 模型正常收尾 | run 结束 | 停在半路，等人再发一句 |
| 上游报错 / 超时 | run 失败 | 已写章节在磁盘上，但不会自动继续 |
| WebSocket 断开 | run 继续 | 服务端能跑，但浏览器关了就不方便 |
| agent 进程重启 | run 丢失 | 只能重新发起 |
| 浏览器关闭 / 睡眠 | run 继续 | 同上 |

**根因不是某个 bug，而是「任务粒度太大 + 没有驱动器 + 没有持久状态」。**

---

## 二、设计原则

1. **一个可恢复单元 = 一节课**。一个 run 只写一课，写不完最多重试一课，不会连累整门课。
2. **进度以磁盘为准**。`lessons/*.md` 存在即完成，天然幂等，重启可重建。
3. **驱动在服务端**。不依赖浏览器标签页；关掉页面也能继续。
4. **恢复需要 key**。BYOK 的密钥只在会话内存里，进程重启后必须由客户端重新下发——这是安全与自动化的取舍。
5. **失败有上限**。每课最多 3 次，指数退避，超限转 `paused`，避免死循环烧钱。

---

## 三、数据模型

`course.json` 增加运行状态（不影响现有字段）：

```json
{
  "id": "llm-gpt-xxxx",
  "status": "generating",          // draft | generating | paused | done
  "driver": {
    "current": "lesson-5",
    "attempts": {"lesson-5": 1},
    "last_error": "429 Too Many Requests",
    "updated_at": 1794907995
  },
  "lessons": [
    {"id": "lesson-1", "title": "...", "order": 1, "status": "done"},
    {"id": "lesson-5", "title": "...", "order": 5, "status": "writing"}
  ]
}
```

- `status` 用于崩溃检测，不替代磁盘事实。
- `attempts` 按课记录，重启后仍有效（避免无限重试）。

## 四、组件

### 1. CourseDriver（learning 插件内）

```text
start(course_id, session_id)     登记驱动
on_lesson_written(course_id)     推进到下一课
on_run_end(session_id)           调度下一课 / 结束
tick()                           扫描兜底（默认 60s，可配）
```

> `tick` 是**扫描间隔**，不是超时。一节课跑 5 分钟，tick 只会看到「会话 busy」然后跳过，不会打断、不会重发。

调度规则：

```text
if 课程状态 != generating: 返回
if 当前会话 busy: 返回
next = 第一个没有正文的课
if next 不存在: status=done, 返回
if attempts[next] >= 3: status=paused, 返回
提交 run（只写这一课）
```

### 2. 单步 Prompt（关键）

驱动每次提交的不是“继续整门课”，而是**明确的一课**：

```text
只完成第 5 课《形状与初始 loss》。
要求：正文 + objective + 1-3 个 practice + assessment。
调用 write_lesson 成功后立即停止，不要开始下一课。
```

这样每轮 run 只有 1–3 次模型调用，中断概率大幅下降，恢复也只需重做一课。

### 2.1 三种时间尺度，不要混

| 参数 | 默认 | 作用 | 触发后 |
|---|---|---|---|
| `tick`（扫描间隔） | 60s | 检查「有没有待写的课、会话是否空闲」 | 什么都不做或提交下一课 |
| `LLM_TIMEOUT`（单次模型调用） | 300s | 单次上游请求上限 | 报错 → 按失败重试 |
| `stall`（整课停滞） | 15min | 一课长时间没有任何新进度 | 判为卡死，取消并重试 |

三者互不替代：tick 再短也不会杀长任务，stall 是唯一会取消运行中的课的阈值。

### 3. 失败处理

```text
上游错误 / 超时 / 模型空转
  → attempts[lesson] += 1
  → 退避 5s / 15s / 45s 后重试
  → 3 次仍失败：status = paused，记录 last_error
```

### 4. 崩溃恢复

进程启动时扫描 `status=generating` 的课程：

- 对应会话还在内存里 → 交给驱动继续
- 会话不在（进程重启）→ `status=paused`，`last_error="agent restarted"`

因为密钥不落盘，**重启后无法无人值守恢复**，只能：

```text
客户端连上 → set_model（key 从 localStorage） → 点「继续生成」 → driver.resume()
```

### 5. 前端

```text
课程页顶部：进度 4/17 + 状态徽章（生成中 / 已暂停 / 已完成）
paused 时：显示暂停原因 + 「继续生成」按钮
```

点击后：下发 `session.set_model` → 发送一个 resume 帧（或直接发继续指令）→ 驱动接管。

---

## 五、为什么不直接在客户端重试

现在的自动续写是**前端**做的，有三个硬伤：

1. 关掉标签页就停
2. 刷新页面后 `attempts` 丢失，可能无限重试
3. 多个标签页会互相抢会话

驱动放在服务端才能解决这三个问题；前端只负责展示和“一键恢复”。

## 七、分阶段

| 阶段 | 内容 | 工作量 | 价值 |
|---|---|---|---|
| **P0** | 单课单 run + 服务端驱动 + 重试/退避 + paused | 1 天 | 解决 80% 中断 |
| **P1** | 前端进度与「继续生成」 | 0.5 天 | 进程重启后可恢复 |
| **P2** | 启动扫描与状态修复 | 0.5 天 | 崩溃后自愈提示 |
| **P3** | 多课程队列、并发上限 | 1 天 | 多用户场景 |

## 八、验收标准

1. 关掉浏览器 10 分钟，课程继续生成
2. 上游返回 429，退避后自动继续，不丢已写章节
3. 杀掉 agent 进程再启动，课程标记 paused，一键继续后从下一课接着写
4. 同一课不会重复写入（幂等）
5. 连续失败 3 次后停止，不无限烧 token

---

## 九、一个明确的取舍

**密钥不落盘 = 进程重启后无法全自动恢复。**

要真正做到无人值守，需要把 BYOK 密钥加密存储在服务端。这和多租户安全、合规、泄露责任直接相关，不建议为省一次点击而做。

所以最终形态是：

```text
进程存活  → 全自动（覆盖断网、关页面、模型报错）
进程重启  → 一键恢复（覆盖崩溃、部署、断电）
```

## 十、落地情况（v2，2026-11-17）

调研 OpenMAIC 后按业界做法调整，已全部实现：

| 项 | 实现 |
|---|---|
| key 落服务端 | `WALLE_HOME/data/model.json`，写入后 `chmod 600`；接口只回后四位；旧浏览器配置首访自动迁移并删除本地明文 |
| 无浏览器续跑 | 启动时有 key 就按课程的 `session_id` + `workspace` 重建无连接会话，驱动立刻接手；没 key 才标 `paused` |
| 紧凑上下文 | 每课前把投影切到「当前」，prompt 带完整大纲（已完成/本轮/待写）+ 本课 lesson_id |
| 失败分类 | 400/401/403/404、无效 key、配额、上下文超限 → 直接 `paused`，不再退避重试 |
| 超时 | 单次模型调用 300s；**首事件 120s**（新加，专治连上不吐字） |
| 断连补发 | 带 seq 的环形缓冲，2000 条 / 256KB 双上限；welcome 回传 seq，attach 支持 `last_seq` |
| 大纲确认 | `create_course` 后状态 `awaiting_outline`，`write_lesson` 被拒；课程页「开始生成」按钮转 `generating` 交给驱动 |
| 驱动归属 | 只驱动本会话创建的课程，多标签页不会抢同一门课 |

默认值：

```text
WALLE_COURSE_TICK=60            # 扫描间隔（不是超时）
WALLE_COURSE_STALL=900          # 单课停滞 15min 取消并重试
WALLE_LLM_TIMEOUT=300           # 单次模型调用
WALLE_LLM_FIRST_EVENT_TIMEOUT=120
WALLE_COURSE_CONFIRM=1          # 0 = 跳过大纲确认（自动化用）
```

已知限制：

1. 客户端目前没有发送 `last_seq`（重连会重置 DOM 并整段重放），协议能力已就绪，启用还需改客户端合并逻辑。
2. 驱动运行中若模型调用 `ask_user`，无人连接时会等到 15 分钟停滞超时才取消。
